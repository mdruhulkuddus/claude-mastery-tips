পার্ট ১: Claude.ai চ্যাট অপটিমাইজেশন

SMART CHATTING STRATEGIES
🕐 সঠিক সময়ে চ্যাট করুন
Anthropic peak ও off-peak সময় অনুযায়ী session limit আলাদাভাবে হিসাব করে। Peak hours-এ একই কাজে বেশি token খরচ হয়।
সময় (বাংলাদেশ) ধরন Token খরচ
সন্ধ্যা ৬:০০ — রাত ১২:০০ Peak দ্রুত শেষ হয়
রাত ১২:০০ — সন্ধ্যা ৬:০০ Off-Peak অনেক বেশি ব্যবহার পাবেন
সাপ্তাহিক ছুটির দিন শনিবার-রবিবার (সারাদিন) Off-Peak সবচেয়ে বেশি ব্যবহার
💡 Pro Tip
ভারী কাজ (বড় ডকুমেন্ট এনালাইসিস, লম্বা কোডিং সেশন) সকাল বা দুপুরে করুন — বাংলাদেশ সময়ে এটা off-peak।
✍️ চ্যাট করার সঠিক পদ্ধতি
প্রতিবার আপনি মেসেজ পাঠালে Claude পুরো conversation history আবার প্রসেস করে। তাই চ্যাটের ধরন সরাসরি token খরচকে প্রভাবিত করে।
✓ এভাবে করুন
  • একটি মেসেজে সব প্রশ্ন একসাথে দিন
  • পরিষ্কার ও নির্দিষ্ট নির্দেশনা দিন
  • নতুন টপিকে নতুন চ্যাট শুরু করুন
  • ফাইল বারবার আপলোড করবেন না
  • প্রয়োজনে output format বলে দিন
✗ এভাবে করবেন না
  • ছোট ছোট মেসেজ পরপর পাঠানো
  • অস্পষ্ট prompt দিয়ে বারবার ঠিক করানো
  • একই চ্যাটে ১০০+ মেসেজ পাঠানো
  • একই ফাইল বারবার আপলোড করা
  • "আরেকটু বড় করো" বলে বারবার revise করানো
⚠️ গুরুত্বপূর্ণ
একটি চ্যাট যত লম্বা হয়, প্রতিটি নতুন মেসেজে তত বেশি token খরচ হয়। ২০-৩০ মেসেজের পর নতুন চ্যাট শুরু করাই ভালো।
⚙️ Feature ম্যানেজমেন্ট
Claude-এর বিভিন্ন feature token খরচ করে। যখন দরকার নেই তখন বন্ধ রাখুন:
1

Extended Thinking বন্ধ রাখুন

যখন সাধারণ প্রশ্ন করছেন বা সহজ কাজ — thinking mode বন্ধ রাখলে অনেক token বাঁচে। জটিল logic, math, বা coding সমস্যায় চালু করুন।

2

Web Search প্রয়োজনে বন্ধ করুন

Search and tools সেটিংস থেকে web search বন্ধ করলে token বাঁচে। যখন সত্যিই current info দরকার তখনই চালু করুন।

3

অপ্রয়োজনীয় MCP Connectors বন্ধ করুন

Google Drive, Gmail ইত্যাদি connector চালু থাকলে প্রতিটি মেসেজে extra token যায়। দরকার না হলে disable করুন।

4

Project Files পরিষ্কার রাখুন

Project-এ অব্যবহৃত ফাইল থাকলে সেগুলো context-এ token নেয়। নিয়মিত পরিষ্কার করুন।

🤖 সঠিক Model নির্বাচন
Model কখন ব্যবহার করবেন Token খরচ
Haiku 4.5 সাধারণ প্রশ্ন, ছোট কাজ, দ্রুত উত্তর সবচেয়ে কম
Sonnet 4.6 মাঝারি জটিল কাজ, কোডিং, রিপোর্ট মাঝারি
Opus 4.6 অত্যন্ত জটিল বিশ্লেষণ ও reasoning সবচেয়ে বেশি
💡 Pro Tip
সব কাজে Opus ব্যবহার করবেন না। বেশিরভাগ কাজ Sonnet-এ চমৎকারভাবে হয়। Opus-এর token cost প্রায় ১.৭ গুণ বেশি — শুধু সত্যিই জটিল কাজে ব্যবহার করুন।
⌨️

পার্ট ২: VS Code-এ Claude Code অপটিমাইজেশন

CODE SMARTER, NOT HARDER
🚨 সবচেয়ে গুরুত্বপূর্ণ কথা
Claude.ai এবং Claude Code একই usage bucket শেয়ার করে। অর্থাৎ VS Code-এ Claude Code ব্যবহার করলে সেটাও আপনার Pro plan-এর session ও weekly limit থেকেই কাটে। তাই দুটো মিলিয়ে পরিকল্পনা করুন।
⚠️ সতর্কতা
Claude Code সাধারণ chat-এর চেয়ে অনেক বেশি token খরচ করে, কারণ এটি ক্রমাগত context, files, এবং tool results প্রসেস করে। একটি কোডিং সেশনে হাজার হাজার token যেতে পারে।
📦 Context ম্যানেজমেন্ট — সবচেয়ে বেশি token বাঁচায়
Claude Code-এ সবচেয়ে বেশি token যায় context size-এ — কত ফাইল ও কোড Claude পড়ছে।
1

CLAUDE.md ফাইল ছোট রাখুন

প্রজেক্টের CLAUDE.md-তে শুধু প্রয়োজনীয় নির্দেশনা রাখুন। অতিরিক্ত ব্যাখ্যা ও ভূমিকা বাদ দিন — এই ফাইল প্রতি মেসেজে প্রসেস হয়।

2

/compact কমান্ড ব্যবহার করুন

লম্বা সেশনে context বড় হয়ে যায়। /compact কমান্ড দিলে Claude আগের কথোপকথন সারাংশ করে context ছোট করে।

3

Milestone-এ নতুন সেশন শুরু করুন

একটি feature শেষ হলে বা একটি বড় পরিবর্তন commit করলে নতুন সেশন শুরু করুন। পুরনো context নতুন কাজে অপ্রয়োজনীয়।

4

.claudeignore ব্যবহার করুন

node_modules, build folders, log files ইত্যাদি ignore করুন যাতে Claude এগুলো context-এ না টানে।

🎯 স্মার্ট Prompting কৌশল
✓ Token-efficient Prompts
  • নির্দিষ্ট ফাইলের নাম বলুন
  • একটি prompt-এ পুরো কাজ বলুন
  • Expected output বর্ণনা করুন
  • Batch edits: একটি diff-এ সব পরিবর্তন
✗ Token-wasting Prompts
  • "এই ফাইলটা ঠিক করো" (কোন ফাইল?)
  • পরপর ছোট ছোট refine করানো
  • "আরেকটু ভালো করো" বলে বারবার
  • একই কাজ ভেঙে ১০ বার বলা
// ❌ খারাপ — ৫টি আলাদা prompt (৫ গুণ token)
"header component বানাও"
"এবার footer বানাও"
"sidebar যোগ করো"
"responsive করো"
"dark mode যোগ করো"

// ✅ ভালো — ১টি prompt (১ বার context process)
"একটি responsive layout বানাও যেখানে
header, sidebar, footer থাকবে এবং
dark mode support থাকবে।
ফাইল: src/components/Layout.tsx"
🔄 Model Switching কৌশল
VS Code-এ /model কমান্ড দিয়ে কাজ অনুযায়ী model পরিবর্তন করুন:
কাজের ধরন প্রস্তাবিত Model কেন
সাধারণ code generation Sonnet দ্রুত, কম token, ভালো output
Bug fixing, ছোট edits Haiku সবচেয়ে কম token খরচ
Complex architecture design Opus গভীর reasoning দরকার হলে
Code review & refactoring Sonnet ভালো balance

/model sonnet   # বেশিরভাগ কাজে
/model haiku    # ছোট কাজে
/model opus     # শুধু complex সমস্যায়
🔧 VS Code-এ Specific টিপস
1

claude.ai থেকে Usage চেক করুন

VS Code extension-এ /status বা /cost কমান্ড কাজ করে না — এগুলো শুধু Claude Code Terminal (CLI)-এর জন্য। Usage দেখতে browser-এ claude.ai → Settings → Usage এ যান। VS Code ও claude.ai একই usage bucket শেয়ার করে, তাই এখানেই সব দেখা যাবে।

2

অপ্রয়োজনীয় Extension বন্ধ রাখুন

Claude Code-এর সাথে অন্য AI extension (Copilot ইত্যাদি) একসাথে চললে conflict হতে পারে ও extra resource যায়।

3

Plan Mode ব্যবহারে সতর্ক থাকুন

Plan/Explore mode অনেক বেশি token ব্যবহার করে কারণ এটি একাধিক ফাইল scan করে। সাধারণ কাজে এড়িয়ে চলুন।

আদর্শ Daily Workflow

MAXIMUM OUTPUT, MINIMUM TOKENS
সকাল

🌅 ভারী কাজ করুন (Off-Peak)

বড় codebase refactoring, document analysis, লম্বা কোডিং সেশন — এই সময়ে off-peak rate-এ token কম যাবে। VS Code-এ Claude Code দিয়ে বড় feature তৈরি করুন।

দুপুর

🌤️ মাঝারি কাজ চালিয়ে যান

Code review, bug fixing, ছোট feature — Sonnet বা Haiku model ব্যবহার করুন। /compact দিয়ে context পরিষ্কার রাখুন।

সন্ধ্যা

🌆 হালকা কাজ (Peak শুরু)

সন্ধ্যা ৬টার পর Peak time শুরু। এই সময়ে শুধু ছোট প্রশ্ন, quick chat করুন। ভারী কাজ এড়িয়ে চলুন।

রাতে

🌙 রাত ১২টার পর আবার Off-Peak

যদি রাত জাগার অভ্যাস থাকে, মধ্যরাতের পর আবার off-peak rate পাবেন।
